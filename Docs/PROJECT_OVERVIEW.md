# PROJECT_OVERVIEW.md -- syscalls-rust

## Суть проекта

**syscalls-rust** -- Rust-реализация SysWhispers3, библиотеки прямых Windows NT syscall'ов. Позволяет вызывать NT API функции напрямую через инструкцию `syscall`/`sysenter`, минуя ntdll.dll и любые user-mode хуки (EDR/AV).

## Целевая аудитория

- Red team операторы
- Пентестеры
- Security исследователи
- Разработчики offensive-инструментов

## Стек технологий

| Компонент | Технология |
|-----------|------------|
| Язык | Rust (edition **2024**, MSRV **1.97**, `#![no_std]`, stable) |
| Архитектура | x86_64, i686 (Windows only) |
| Сборка | Cargo, custom build.rs для C header |
| C биндинги | staticlib + cdylib, автогенерация .h |
| Лицензия | MIT |

## Ключевые возможности

1. **513 NT syscall функций** -- полный набор (память, процессы, потоки, файлы, реестр, токены, синхронизация и т.д.)
2. **Прямые syscall'ы** -- `syscall` (x64) / `sysenter` (x86), без вызова ntdll
3. **Хеш-обфускация** -- имена функций не появляются в бинарнике (ROR8 hash + seed)
4. **JUMPER_RANDOMIZED** -- подмена return address через случайный syscall адрес в ntdll
5. **Нулевые зависимости** -- `#![no_std]`, нет libc, нет внешних крейтов
6. **C/C++ биндинги** -- полная поддержка с автогенерацией заголовка `syscalls.h`
7. **Dual architecture** -- x86 и x64 с полной поддержкой WoW64 (dummy return address, params array)

## Бизнес-логика

При первом вызове любой syscall-функции:
1. Читается PEB (Process Environment Block) через `gs:[0x60]` / `fs:[0x30]`
2. Находится ntdll.dll в списке загруженных модулей
3. Парсится export table, собираются все Zw* функции
4. Функции сортируются по адресу -- индекс = номер syscall
5. Хешируются имена, находятся адреса syscall инструкций
6. Таблица кешируется в static mut (однократная инициализация)

При каждом вызове:
1. По хешу находится номер syscall и адрес syscall инструкции
2. Параметры размещаются в регистрах по calling convention
3. Выполняется `jmp` на syscall инструкцию в ntdll (JUMPER mode)
4. Возвращается NTSTATUS
